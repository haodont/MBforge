# 专利活性提取：瓶颈、对照实验与精简记录

日期：2026-10-29。状态：本轮诊断与局部修复验证完成；OXR已完成6次裁剪推理，尚未切换生产后端或证明全链路收益。

## 目标与边界

目标是得到可核实的「印刷读数 → 指代 → 具体结构 → 实验条件」，而非最大化
Markdown 长度、分子数或模型回答数。原 PDF/图像是核实来源，SQL evidence 是
流水线账本；LLM/OXR 输出是待验证候选，不能直接覆盖已确认事实。

当前工作树已有大量用户改动。本轮修改编号继承、单元格归属几何、显式表头跨度和实施例指代解析，
删除质量单独补配分支，并调整最近的既有测试及相关说明；没有重置工作树，
没有重跑或发布生产库专利分析。
实验材料、原始响应和部署日志不进 Git；key 继续只从本地 settings 读取。

## 当前结论

OCR是瓶颈之一，不能代表整个文档识别瓶颈。已有实证中，文字已读对但
单元格归属/HTML跨度/指代命名空间/SQL投影仍会产生错误；另一些复杂结构表和
日文正文则确实受内容识别拖累，OXR有帮助。

本轮选择先落地小范围本地修复，保留服务器OXR作为困难材料的对照候选。
未改正式文献库，未切换生产后端；13文档旧证据的36条读数/11条结构关联
不能当准确率，也不能拿它代表新OCR重新跑全库的结果。

## 实验1：空编号是否可以继承左侧编号

CN121270515A PDF第20页的图像明确印着：

```text
实施例编号 | MRGPRX2抑制活性 | 实施例编号 | MRGPRX2抑制活性
5          | ++++           | 6          | ++++
```

存储的OCR丢掉了`6`。原实现`_pair_owner`向左遍历并跳过活动值，
把右侧`++++`归给`5`；既有测试还把这个结果认定为「合并单元格」。
图像与`gold-pilot-cn121270515a-20261023.md`、`patent-layout-rules.md`均反证了它。

已删除跨列继承助手，解析器只接受当前值对应编号列的明确指代。
缺编号使现有完整性检查失败，进入`complex_activity_table`待核实，
不复制`5`，也不按数列猜`6`。同一编号列下的多个指标仍正常读取。
真正的合并单元格必须由图像/显式span证据证明，Markdown空白本身不能证明。

这次读数减少7条来自该表整体拒绝；其中并非7条都错误。现有整表拒绝策略
保住正确性但损失可用的单元格，是下一阶段要单独评估的覆盖率成本。
既有事实不因修改解析代码自动消失；旧产物中的错配需要审查后重建，
本轮未直接修改持久化事实。

## 实验5：OCR正确仍会发生靶点错列

8表接入下游后发现，`html_table_to_markdown`原先忽略显式
`rowspan`/`colspan`，将下一行单元格一律从第0列排列。
这不是文字识别错误，而是已识别结构在转换中丢失。

原图人工核实CN121270515A第21页：左侧「化合物编号」跨两行，
「IC50 (nM)」横跨MRGPRX1/2/3/4四列。

| 输入/输出 | 12条读数的列靶点（每行4条） |
|---|---|
| 原转换 | MRGPRX2、MRGPRX3、MRGPRX4、空 |
| 显式span展开后 | MRGPRX1、MRGPRX2、MRGPRX3、MRGPRX4 |

第20页表也由左侧读数缺靶点变为7条均保留MRGPRX2。
8表所有已读值保持相同；CYP3A4不同底物仍区分。
转换器只展开HTML明确声明的span，不推测Markdown空格；
非法/重叠/异常大span返回不可用内容，保持既有best-effort边界。
通用「活性/结果/数值」子表头不覆盖上一层的真实靶点。
最近的既有活性使用测试增加两个实测HTML形状，保护最终值所属靶点，
未重复创建内部实现测试。

## 专利中的活性记录与指代模型

| 记录方式 | 必须读取的上下文 | 到结构的路径 / 主要误配风险 |
|---|---|---|
| 每行一个化合物，多指标列 | 多层表头、靶点、单位、底物、浓度 | 化合物号→声明/结构；不同测定列不能合成一个scalar |
| 一行重复多组编号和值 | 每组编号列及其表头命名空间 | 每组独立指代；空格不等于合并，不跨组继承 |
| 按实施例汇总活性 | 实施例号、制备段最终产物 | 实施例→产物→检出结构；不等于同号化合物或中间体 |
| 结构图直接作为表格一列 | 结构单元格与值的行列对应 | 图像结构→MolParser候选→该行读数；原子文字不是编号 |
| 正文单值/范围或多编号列表 | 比较符、端点、单位、列表作用域 | 显式指代→条目；一个范围不是精确值，列表不随意缩成一条 |
| A/B/C或+/++/+++分档 | 对应实验的分档定义、上下界开闭 | 保留原档位与定义；不取中点，不跨assay借legend |
| 跨页表格、旋转表、多行表头 | 表号、续表标记、表头与方向 | 先恢复表结构；不能仅凭页距连行/借表头 |
| 外部专利、阳性对照、参考化合物 | 来源文献+内部编号/名称 | `(来源, 指代类型, 编号)`共同定位，不能当本专利Compound1 |
| 仅图中曲线/剂量反应 | 图例、坐标、误差、条件 | 另行记录图形证据；未数字化/未印刷IC50不伪造精确值 |

每条读数还需实验身份：species、target、endpoint、assay、底物/激动剂、
浓度/时间等。保留原值、单位、比较符和证据位置；ND/NA/NT是缺测。
IC50、pIC50、抑制率、PK/ADME指标应保持语义区分。

指代至少区分：本专利compound号、example号、preparation/intermediate号、
印刷化学名称/内部代码、外部来源编号、Markush/formula。名称只在有明确别名声明
或经过验证的名称解析时连接结构；不能用相似字符串合并盐、异构体或同位素体。
一个实施例可有多步中间体或多个最终产物；找不到唯一产物时保留歧义。

本轮还纠正了gold文档/schema说明中的错误：「标准InChIKey不编码同位素」。
实际是**首段连接块**不能区分同位素体，完整key可以。
本机RDKit自检甲醇与甲醇-d3分别得到
`OKKJLVBELUTLKV-UHFFFAOYSA-N`、`OKKJLVBELUTLKV-FIBGUPNXSA-N`；
首段相同、完整key不同。保留`exact_isotopes`的规范SMILES比较约定，
只修改错误解释，未重写任何结构或标注结论。

最小的业务链：

```text
图像/文字证据 → 原始读数+表头/方法 → 印刷指代
                                      ↓
                         本文档编号/实施例/名称索引
                                      ↓
                             有证据的具体结构候选
```

这里需要的是可追溯索引，不需要再建一个任意关系知识图谱或第二份证据库。
