## What the pilot establishes

### 1. The contract works for all four relation shapes

- `claim_scope` binds claim text to a Markush scaffold (`esmiles` + evidence id),
  without enumerating the genus.
- `designated_as` binds a printed compound number to a molecule.
- `exemplified_by` binds an example number to its product.
- `reported_as` binds a table reading to the compound that owns it.
- `absent` records capture both an external patent reference and a
  non-compound example.

Both validators accept every record:

```
uv run python tests/gold/validate.py tests/gold/annotations/cn121270515a.pilot.jsonl
manifest: 13 documents
records: 22 valid, 0 invalid
```

The JSON Schema also accepts all 22 (`jsonschema`, 2020-12).

### 2. OCR dropped a table label; the page image corrects it

Page 20 prints two label/value columns:

```
| 实施例编号 | MRGPRX2 抑制 | 实施例编号 | MRGPRX2 抑制 |
| 1          | ++++         | 2          | ++++         |
| 3          | ++++         | 4          | ++++         |
| 5          | ++++         | 6          | ++++         |
| WO2022067094 | +++        |            |              |
```

The OCR table text is `| 5 | ++++ | | ++++ |` — the `6` label was lost. The
record `cn121270515a:p20:table:row6:reported_as` carries this in
`anchor.ocr_issue`. This is exactly the class of error the page-image rule
exists for.

### 3. `实施例N` and `化合物N` are different sets

Claim 4 lists six compounds. They are **not** the same six as Examples 1-6:

| Claim 4 | Substituent | Example | Substituent |
|---|---|---|---|
| compound 2 | `OCH3` phenyl, protio quinoline | Example 2 | `OCD3` phenyl, protio quinoline |

Both share the InChIKey connectivity block `QUZSBIUCNMMGOO` because standard
InChIKey's first block describes connectivity; their full keys differ. They are
different structures. The table
header is `实施例编号`, so its row 2 binds the **Example 2** structure, never
claim 4 compound 2. The `@example:N` / `N` key-space split is load-bearing, not
cosmetic.

### 4. The detector disagrees with itself across locations

| Pair | InChIKey | Finding |
|---|---|---|
| claim 4 c1 / Example 1 | `IFPVOGRWDPFTCR-IJNKOPBPSA-N` / `IFPVOGRWDPFTCR-IBZLBPKTSA-N` | Same connectivity, different stereo at one cyclohexyl centre |
| claim 4 c3 / Example 3 | `UMFGGOLYSCWFQW-ULKOHKRGSA-N` / `IFPVOGRWDPFTCR-VVQOKKTDSA-N` | Different connectivity blocks; one location is a different constitution |
| claim 4 c2 / Example 2 | `QUZSBIUCNMMGOO-DLBZAZTESA-N` / `QUZSBIUCNMMGOO-UXJJITADSA-N` | Different isotope composition (`OCH3` vs `OCD3`); only the connectivity block coincides |

The pilot records the location-specific structure and flags the disagreement;
it does not silently pick a winner. The two disputed pairs use
`identity_level: "connectivity"`, the consistent ones use `"exact_isotopes"`.

### 5. A schema gap was found and fixed

`exact_isotopes` was added to the gold schema and validator to avoid comparing
isotopologues by their connectivity block alone. Full InChIKeys do distinguish
isotopes. The evaluator compares RDKit
canonical isomeric SMILES at this level. The taxonomy and protocol were updated
in the same change.

### 6. The table anchor is coarse

The current table evidence row covers the whole table; per-cell bboxes are not
stored. All six `reported_as` records use the table bbox. The pair is still
valid, but anchor IoU matching is coarse and six rows share one anchor. Extract
must emit per-row/cell `label_anchor` rows before table precision can be
measured fairly.

## What this pilot does not establish

- **No adjudication.** The protocol requires two independent annotators and a
  third adjudicator; this is one annotator's draft.
- **No metric.** The current pipeline does not yet write `relation_pair`, so
  there is no pair-level comparison. The 22 records are the reference for that
  comparison.
- **No structure certification.** The structures come from the detector and were
  checked against the drawing at the substituent/isotope level. The stereo and
  connectivity disagreements above need a human chemist.
- **One document.** The protocol's pilot is two documents; the second is the
  next pass.
